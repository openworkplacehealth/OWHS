Your file stays in this browser

  • The file is read and checked on this page. It is not uploaded, stored or sent anywhere, and this page has no visit counter.
  • The page's security policy lets it fetch only from openworkplacehealth.org, and the only things it fetches are its own files: the page itself, then the checker the first time you press Check. After that it makes no requests at all, so it keeps working with your connection switched off. Your browser's network panel will show this.
  • Even so, use synthetic or test records. Do not paste real personal data.

    What a pass means
    
    
    A pass means the file is structurally conformant: it meets Level 1 of the specification's three conformance levels. It is not a compliance finding, a certificate or a privacy assessment. For one record the check is:
    
    
      
      
    • the record against its v{{SCHEMA_VERSION}} JSON Schema: required fields, types, patterns, code values written into the schema, and no field the schema does not declare;
      • 
      
    • every format asserted, so a date has to be a real date;
      • 
      
    • the restrictions on extension keys inside ext, including the ban on identifier and clinical key names;
      • 
      
    • the named within-record rules C1 to C18 that apply to its type.
      • 
    
    
    
    For a bundle, the entity-graph checker runs the same checks on every record, then the relationship checks G01 to G10 and the measurement checks described in the entity-graph guide, and lists what it could not establish.
    
  
    
  
    
    
    What it does not check
    
    
      
      
    • Level 2: whether each coded value resolves to a current code-list version.
      • 
      
    • Level 3: the privacy obligations. Whether an output is safe to disclose, whether a declared count is true, whether a value withheld by omission should have been suppressed, and whether a field reaches only the people its visibility class allows. The specification says plainly that no tool can verify these from a file alone.
      • 
      
    • Identifiers or sensitive meaning hidden inside permitted text values.
      • 
      
    • References to records that are not in the file, and what an extension profile requires when no profile is supplied.
      • 
    
    
    
    The privacy profile sets out the obligations a producer carries whatever this page says.
    
  
    

    


    
  
    The same code as the reference validator
    
  
    This page does not reimplement the rules. It runs tools/validate.py and tools/check_entity_graph.py from the repository, unchanged, in Python {{PYTHON_VERSION}} compiled to WebAssembly (Pyodide {{PYODIDE_VERSION}}) with jsonschema {{JSONSCHEMA_VERSION}}. The Python tools are the reference; this page is a way to run them without installing anything. A test in the repository runs all {{ALL_FIXTURES}} example files ({{RECORD_FIXTURES}} single records and {{BUNDLE_FIXTURES}} bundles) through the command-line tools and through this page in a headless browser, and fails on any difference in the verdict or in the rules reported.
    
  
    To run the same check on your own machine: python tools/validate.py schemas/v0.2/AbsenceEpisode.json your-file.json. Every file this page loads, with its source and licence, is listed in the vendor manifest. Reference validator SHA-256 begins {{VALIDATE_SHA}}.

    The Open Workplace Health Standard is an early open specification, created by Zak Fenton and currently stewarded by Alltoogether, which builds products that may implement it. It is open to inspect, use, challenge and improve. If it earns independent use and recurring contribution, its governance will move to a multi-stakeholder structure so that no single commercial organisation controls its future.
