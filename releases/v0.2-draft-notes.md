# OWHS v0.2-draft: release notes (draft, for the owner to publish)

This file is the text for a first tagged release of the repository's current state. It is not a release and no tag exists. Counts are as at 19 November 2026; check them against the repository before publishing.

## What this release is

A snapshot of the Open Workplace Health Standard repository: the v0.2 draft specification, its schemas and code lists, the instrument evidence registry, the question bank, the generators and checks, and the site source. The specification is a draft published for review. Nothing in the release is a final standard, a certification or a recommendation of any instrument.

## Stated limits, to carry into the release text

- Every registry grade was assigned by one rater employed by the steward. Grades and statuses are frozen until two named psychometric raters who are not employees of the steward have joined. Grades are not comparable across instruments and are not a recommendation.
- Registry version 0.9.0 had five citations appended in place on 19 November 2026 without a new version number. A release made from this state fixes the content at its commit.
- Conformance Levels 2 and 3 are specified and not implemented as checks; Level 1 is structural.
- No month has yet been recorded as verified by the evidence cycle (`evidence/watermarks.json` is empty), and October 2026 has no verified search. See https://openworkplacehealth.org/status.html.
- No DOI exists. A DOI is created only if Zenodo archives this release (see below).

## Suggested release title and short text

Title: `OWHS v0.2-draft`. Mark it as a pre-release.

Text: the first tagged snapshot of the Open Workplace Health Standard: the v0.2 draft specification with its schemas and code lists, the instrument evidence registry (dataset 0.9.0) and the question bank (0.2.0), with the tools that generate and check them. A draft for review, not a final standard. Licences: text CC BY 4.0, schemas, code lists, dataset structure and tools Apache 2.0. Third-party instrument and survey-item wording stays with its source.

## To cut it, in order

1. Confirm `main` is green on the `validate` workflow and that the pull requests meant for this snapshot have merged.
2. If a DOI is wanted: sign in to Zenodo with the GitHub account that owns the organisation, enable the repository under the GitHub integration, and check the record preview of `.zenodo.json` (creators, licence, upload type). Do this before step 3; Zenodo archives only releases made after it is switched on.
3. On the repository's Releases page, draft a new release, create the tag `v0.2-draft` on `main`, tick pre-release, paste the text above, and publish.
4. After Zenodo has made the record, add its DOI to `CITATION.cff` as an `identifiers` entry and to the how-to-cite generator (`tools/build_cite.py`), rebuild, and add a changelog entry. Until then every page says versions are identified by version number and address.
5. Watch Releases on the repository (Watch, Custom, Releases) to see it appear.
