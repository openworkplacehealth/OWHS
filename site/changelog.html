One Moderate returns to High (k10 internal consistency, capped in v0.5.0 on a coding error), five High cells drop to Moderate, four single-item invariance cells and one derived-index structure cell become Not-applicable, three flags move, 24 cells are recoded off mixed, 29 cited studies leave the High-basis tables for want of a statistic of the property. v0.5.02 Sep 2026Reconciliation of the review pass of v0.4.0, before first publication. Rubric v1.2: the indirectness flag has three values (direct, general, indirect), each cell states the studies its flag rests on, a grade never moves because a flag moved, and a High grade needs at least two cited studies with a sample size and a statistic, listed on the cell. The six C-0004 grade moves are reversed and six further High cells drop to Moderate (three for want of the numbers, two for indirect evidence on a population-sensitive property, one for a mixed cell that names no second form); 49 flags change; six criterion cells that had been graded on a reference standard the construct does not have become Absent (category error); four not-applicable cells become Absent and one Absent cell becomes not-applicable. Every Absent or Not-applicable cell names its absence type and carries no flag. Schema 0.5: indirectness_basis, absence_type, high_basis, a corresponds-with relation for single items whose only published link to an instrument is a correlation, and a generated integrity block. The site build now fails on any cell that breaks these rules. All logged as correction C-0005 with the rubric 1.1 values kept on each changed cell. No fresh literature search: as-of dates unchanged.
v0.4.02 Sep 2026Purpose reset before first publication. The registry's purpose is stated: the open synthesis of the published evidence on instruments used to measure workplace health and wellbeing, scope the whole field by construct, the first 27 instruments stage one. Rubric v1.1: indirectness is defined by population type, never by country or language; every cell re-read, 92 flags changed and 6 grades moved (all upward, all occupational instruments), logged as correction C-0004 with the rubric 1.0 values kept on each cell. Schema 0.4: every indirectness flag carries its reason; relations on every record link single items and short forms to the multi-item instruments they were validated against, each citing its study; new single-item measures page. Freeze dated from first publication. Search venues and strings published on the methods page. No fresh literature search: as-of dates unchanged.

Specification

VersionDateWhat changed
v0.14 Sep 2026Closed-vocabulary rule added to section 5: a fixed set of values is bound to a registered code list, and the correspondence between an inline enum and the list its $comment pins is a Level 2 obligation no tool here checks. rtw-sustained-status@0.1.0 created for the one field that lacked a list, values unchanged. Error map corrected: the AbsenceEpisode invalid instance raises four errors, not five, and the rule the fifth named is not in any schema; rows added for the three date fixtures. The repository copy's link to its own validation report resolved to a directory that does not exist and is fixed. A declared dependency, a workflow that runs the report gate, and --check on the generator, which previously ignored its arguments and overwrote the file it was asked to check.
v0.14 Sep 2026Both RFCs opened for comment, with a window of 7 September to 17 October 2026 and an issue each as the comment thread: RFC 0001, the construct-domain code list at v0.2, five admissions, two new fields on every code and a mapping from the question bank's topic groups; and RFC 0002, whether a construct about an identified person, such as a manager rated by their team, enters the vocabulary at all, and under what rule. The aggregation floors protect respondents and do nothing for subjects, and RFC 0002 gates RFC 0001: no subject-identifying code is admitted until it is settled.
v0.14 Sep 2026Corrections after an external technical review, each one reproduced before it was fixed. The reference validator did not assert format, so any string passed where a date was declared; it now asserts every format and refuses to run rather than report a pass it cannot stand behind. An allOf member said end dates must not precede start dates and enforced no ordering; date ordering within a record is now the named rules C1 and C2 at Level 1, implemented in the validator, because JSON Schema cannot compare two fields of an instance. A direct-identifier member duplicated additionalProperties: false and claimed to forbid identifiers "anywhere", which was untrue of values; the privacy profile now separates what is enforced from what is a producer obligation. value on AggregateReport was unconditionally required while section 9 required a producer below a floor to suppress and not emit it, so no conformant suppressed report could exist; corrected with an erratum. Level 3 now states that no tool in the repository verifies it, and why parts of it cannot be verified from a payload at all. Full detail in CHANGELOG.md.
v0.13 Sep 2026Text revision, nothing normative: section 7 examples use the profiles the specification itself defines (owhs-msk, owhs-ohsurveillance) and the steward's own profile is described by its role rather than by name; the safeguarding-category anchor says the same. The rendered page, the markdown and the bundle are regenerated from the source.
v0.1Jul 2026First public draft: entity catalogue, JSON schemas with conformance examples, 23 versioned codelists, privacy profile, reference validator, four open RFCs.
